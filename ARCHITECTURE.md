# Архитектура

Сервис отвечает на один вопрос: какая позиция каталога «Своё Вино» изображена
на фотографии этикетки. Он возвращает одну карточку, карточку с оговоркой
и вариантами или честный отказ, «не удалось уверенно определить». Числа
качества — в [README](README.md), методика замеров — в
[docs/metrics.md](docs/metrics.md).

## Общая схема

```mermaid
flowchart LR
    user(["Телефон или браузер"]) --> web["web/ — Nuxt 4<br/>скан, карточка, страницы вин"]
    judge(["Скрипт оценки<br/>кейсодержателя"]) --> api
    web --> api["service/main.py — FastAPI<br/>/v1/search · /v1/eval/predict<br/>/v1/analogs · /v1/wines · /v1/photo<br/>/v1/sommelier · /health"]
    api --> core["pipeline/searchcore.py<br/>общий конвейер поиска"]
    api --> rec["service/recommend.py<br/>гастропары, аналоги, сомелье"]
    core --> models["Модели<br/>YOLO11m · SigLIP 2 · EasyOCR · Qwen3-VL-4B"]
    core --> store[("Индекс эталонов<br/>numpy в памяти или PostgreSQL + pgvector")]
    core --> sift[("Признаки SIFT эталонов<br/>memory-map")]
    api --> catalog[("data/catalog/catalog.json<br/>2103 позиции")]
```

Один и тот же модуль `pipeline/searchcore.py` вызывают сервис, калибровка
и все замеры. Поэтому пороги подбираются ровно для того конвейера, который
отвечает пользователю.

## Конвейер запроса

```mermaid
flowchart TD
    photo["Фото этикетки"] --> views["1 · Два вида кадра<br/>целиком и кроп по бутылке YOLO11m<br/>imageprep.py"]
    views --> emb["2 · Эмбеддинг SigLIP 2 so400m-384<br/>1152 измерения на вид · embed.py"]
    emb --> short["3 · Шортлист<br/>косинус против 4182 векторов<br/>(2091 позиция × 2 вида),<br/>свёртка по slug максимумом, топ-20"]
    short --> geo["4 · Геометрия<br/>SIFT, тест Лоу 0.75, гомография RANSAC<br/>порядок меняется, если у лидера<br/>≥ 1.5× точек второго · rerank.py"]
    geo --> text["5 · Текст этикетки<br/>EasyOCR, правила по винодельне,<br/>имени, цвету, сладости и году<br/>text_match.py"]
    text --> conf["6 · Уверенность<br/>7 относительных признаков →<br/>логистическая модель confidence.json"]
    conf --> vlm["7 · VLM Qwen3-VL-4B<br/>подтверждение, арбитраж,<br/>проверка полосы 0.10–0.30,<br/>спасение отказа по этикетке<br/>vlm_verify.py · vlm_label.py"]

    out -->|"p ≥ 0.30, без оговорок"| c1["одна карточка"]
    out -->|"p ≥ 0.10 и VLM не отвергла<br/>или подтверждено VLM"| c2["карточка с оговоркой<br/>и вариантами"]
    out -->|"иначе"| c3["«не удалось уверенно определить»,<br/>аналоги по этикетке, похожее по виду"]
```

### 1. Два вида кадра

`pipeline/imageprep.py`: YOLO11m находит бутылки, выбирается целевая,
крупная и ближе к центру. Дальше идут оба вида: кроп по бутылке и кадр
целиком. Если детектор взял не ту бутылку, второй вид всё равно даёт
шанс найти вино.

### 2–3. Отбор кандидатов

SigLIP 2 so400m-384 (`pipeline/embed.py`) переводит каждый вид в вектор
на 1152 измерения. Каждая позиция каталога описана так же, двумя векторами
по её эталонному фото. Косинус считается против всех 4182 векторов индекса,
по каждой позиции берётся лучший, и выдача сворачивается по slug. В
шортлист идут 20 позиций. Индекс хранится в памяти (numpy) или в
PostgreSQL с pgvector (`VECTOR_BACKEND=pgvector`). База делает точный поиск,
косинус пересчитывается по тем же float32-векторам, поэтому шортлисты
в обоих вариантах совпадают.

### 4. Геометрическая проверка

Эмбеддинг отвечает на вопрос «похожая ли этикетка» и путает позиции одной
линейки. Их отличает мелкий шрифт. Геометрия отвечает на другой вопрос —
«та же самая этикетка» (`pipeline/rerank.py`):

- точки SIFT на кадре приводятся к 700 px по длинной стороне, берётся до
  1200 точек;
- соответствия с эталоном проходят тест Лоу 0.75;
- гомография RANSAC с допуском 5 px оставляет инлаеры, то есть точки,
  которые легли на одно преобразование.

Признаки всех эталонов посчитаны заранее и открываются через memory-map.
Для геометрии берётся тот вид кадра, который лучше узнал каталог.

Порядок по точкам заменяет косинусный, только если у лидера по точкам
совпавших точек не меньше чем в 1.5 раза больше, чем у второго
(`GEOMETRY_MARGIN=0.50`). Иначе геометрия считается нерешающей, и порядок
остаётся по косинусу: у линеек с общей этикеткой разница в точках —
шум, а не свидетельство.

### 5. Текст этикетки

EasyOCR один раз читает кроп (`pipeline/ocr.py`). Прочитанные строки
проходят через правила `pipeline/text_match.py` и шаг `searchcore.settle`:

- **винодельня.** Уверенно прочитанное имя винодельни, принадлежащее одной
  из виноделен шортлиста, выводит её вина вперёд;
- **разрешение близких.** Если геометрия не развела лидеров (у соседа не
  меньше 80% точек лидера), кандидаты сравниваются словами. В группу
  добавляются и владельцы уверенно прочитанного имени вина. Кандидат,
  у которого прочитанного различающего слова нет, опускается;
- **противоречие лидеру.** Прочитанные цвет, сладость или год, которые
  противоречат карточке лидера, отправляют его вниз;
- **проверка лидера.** Улики против лидера и подтверждения за него идут
  в признаки уверенности.

Сравнение слов учитывает смешение кириллицы и латиницы («KPACHOЕ») и
транслитерацию имён. Нечёткое совпадение допускается только при
уверенном чтении.

### 6. Уверенность

`searchcore.features` считает семь относительных признаков лидера:

- доля его точек в паре с прямым соперником;
- логарифм числа точек;
- отрыв по косинусу от соперника;
- превышение над хвостом шортлиста;
- покрытие этикетки совпавшими точками;
- поддержка текстом;
- улики против лидера.

Признаки относительные, потому что абсолютные шкалы на снимке с полки
другие, чем на эталоне. Логистическая модель (`data/index/confidence.json`,
`pipeline/calibrate.py`) выдаёт две вероятности:
- P(лидер верен);
- P(верный ответ в пятёрке).

Модель обучена на синтетике из эталонов дампа и на настроечной части
снимков организатора.

### 7. VLM: подтверждение и арбитраж

Qwen3-VL-4B-Instruct (`pipeline/vlm_verify.py`) получает кадр, до трёх
эталонов кандидата и поля его карточки. Ответ — P(yes) на вопрос «тот ли
это товар», по логитам «yes/no». VLM не переставляет пятёрку сама, она
вызывается в трёх ситуациях — при отказе, при прочитанном противоречии
и в полосе «скорее всего» (уверенность 0.10–0.30, `VLM_BAND_VETO=1`):
если там VLM явно отвергает лидера (P(yes) < 0.05), кадр идёт путём
отказа. Так не проходят вина вне каталога, оформленные как линейка из
каталога: Дивноморское «Вторая линия» раньше показывалось как «Холодный
Туман» (на снимках организатора org067 и org093).

Последний шаг пути отказа — спасение по этикетке (`LABEL_RESCUE=1`, по
умолчанию): та же модель коротким промптом читает винодельню и название
(`pipeline/vlm_label.py`, около 1.2 с), `recommend.by_label_name` находит
по ним позицию — среди вин этой винодельни, а если её в каталоге нет, по
всему каталогу, при сходстве названия от 0.6, — и верификатор проверяет её
с тем же порогом 0.8. Позиция может быть и вне шортлиста.

```mermaid
flowchart TD
    start["Лидер после шагов 1–6"] --> q1{"p < 0.10?"}
    q1 -->|да| v1["VLM проверяет лидера"]
    v1 -->|"P(yes) ≥ 0.8"| show["показать лидера<br/>с оговоркой"]
    v1 -->|иначе| fb["VLM проверяет ещё двух<br/>следующих кандидатов<br/>VLM_FALLBACK=2"]
    fb -->|"первый с P(yes) ≥ 0.8"| sw1["он становится ответом"]
    fb -->|никто| geo{"Лидер отвергнут (P < 0.5),<br/>у проверенного P > 0.5<br/>и геометрия за него?<br/>VLM_GEO_FALLBACK"}
    geo -->|да| sw3["он становится ответом"]
    geo -->|нет| lr["Этикетка: винодельня и название →<br/>позиция каталога<br/>LABEL_RESCUE"]
    lr -->|"P(yes) ≥ 0.8"| sw4["она становится ответом"]
    lr -->|иначе| abst["отказ"]
    q1 -->|нет| q2{"Прочитано слово чужой карточки,<br/>которого у лидера нет?<br/>VLM_CONTRA"}
    q2 -->|нет| band{"p < 0.30?<br/>VLM_BAND_VETO"}
    q2 -->|да| v2["VLM проверяет лидера"]
    v2 -->|"P(yes) ≥ 0.5"| band
    v2 -->|"P(yes) < 0.5"| own["VLM проверяет владельцев слова"]
    own -->|"P(yes) ≥ 0.7"| sw2["владелец становится ответом"]
    own -->|никто| band
    band -->|нет| keep["ответ лидера"]
    band -->|да| v3["VLM проверяет лидера,<br/>если ещё не проверен"]
    v3 -->|"P(yes) ≥ 0.05"| keep
    v3 -->|"P(yes) < 0.05"| fb
```

«Геометрия за него» — у кандидата не меньше 80% совпавших точек лучшего
в шортлисте и в 1.5 раза больше, чем у отвергнутого лидера. Это второе,
независимое свидетельство для «скорее да» от VLM: одна VLM в полосе
P(yes) 0.5–0.8 чаще подтверждает соседа по линейке, чем верное вино.

Слово «чужой карточки» — уверенно прочитанное (≥ 0.85) слово от пяти букв,
близкое к слову названия, сорта или винодельни другого кандидата по
расстоянию Дамерау–Левенштейна (до 20% длины). Примеры — «ЦИТРОН», «АЛУШТА».

### 8. Выдача

`/v1/search` возвращает состояние, карточку, варианты, обе вероятности,
данные VLM и тайминги по ступеням. Состояния:

| состояние | условие | что видит пользователь |
|---|---|---|
| `confident` | P ≥ 0.30, против лидера нет улик, а если рядом близкие соседи по линейке — текст подтвердил именно его | одна карточка |
| `uncertain` | P ≥ 0.10 и VLM не отвергла лидера (при P < 0.30 — P(yes) ≥ 0.05), или ответ подтвердила VLM | карточка «скорее всего», свёрнутый блок «Не оно?» |
| `unsure` | иначе | «не удалось уверенно определить», аналоги по этикетке, похожее по виду |

`/v1/eval/predict` — контракт скрипта оценки: `{"slug": "..."}`. При
`EVAL_ABSTAIN=1` (по умолчанию) там, где карточка не была бы показана,
возвращается `{"slug": null}`.

`service/recommend.py` добавляет к найденному вину гастропары, похожие вина
других виноделен и подбор «Цифрового сомелье» по трём вопросам. Аналог
совпадает с вином по цвету, сладости и игристости; сладость берётся из того
же `TextChannel`, что у распознавания (slug, карточки платформы, проверенные
этикетки), и из названия, если там её нет.

### 9. Вино не найдено: аналоги по этикетке

При `unsure` интерфейс отдельным запросом отправляет снимок в `/v1/analogs`.
Qwen3-VL, уже загруженная для подтверждения, читает с кропа бутылки
винодельню, название, цвет, сладость, игристость и сорта
(`pipeline/vlm_label.py`); слова, переписанные с этикетки, важнее
классификации моделью. Прочитанное приводится к словарю каталога, и
`recommend.py` отдаёт вина той же винодельни (ближайшее по названию первым)
и аналоги других виноделен. Без видеокарты стиль читает OCR — только цвет
и сладость.

Чтение идёт после ответа поиска и на него не влияет; `GPU_LOCK` не даёт
ему выполняться одновременно с поиском. Скрипт оценки этот эндпоинт не
вызывает.

Короткое чтение для спасения отказа (шаг 7) — отдельный вызов той же
модели внутри поиска; полное чтение для аналогов в ответ поиска не входит.

## Интерфейс

`web/` — Nuxt 4 без серверного рендеринга. Модуль рассчитан на встраивание
в каталог портала.

- **Страницы:** сканер с результатом (`/`), страница вина (`/wine/<slug>`)
  с карточкой, гастропарами и похожими винами, сомелье без сканирования
  (`/sommelier`).
- **Результат:** уверенный ответ — одна карточка; спорный — карточка,
  свёрнутый блок «Не оно?» и миниатюра своего снимка; отказ — аналоги по
  этикетке (`/v1/analogs`) и похожее по виду. Технические числа — только
  с `?debug`.
- **Сомелье** после скана берёт вкус найденного вина и говорит, подходит
  ли оно к выбранному блюду. Недавние сканы хранятся в браузере.
- **Фото:** увеличивается по касанию.
- **Навигация:** результат поиска хранится в общем состоянии, поэтому
  «Назад» возвращает к нему без повторного сканирования.
- **Адрес API:** берётся из `NUXT_PUBLIC_API_BASE`, а если он не задан —
  из адреса страницы (тот же хост, порт 8080). Так интерфейс, открытый
  с телефона по адресу компьютера в локальной сети, работает без
  пересборки.

- **Образ.** В образ входят код сервиса и веса YOLO11m и EasyOCR. Каталог,
  индексы и дамп монтируются только для чтения.
- **Веса SigLIP и Qwen3-VL** скачиваются при первом старте в том
  `hf-cache`.
- **Старт.** Сервис загружает индекс в pgvector (при изменении — по хешу),
  прогревает модели пустым кадром и только потом отвечает.
- **Видеопамять:** около 12 ГБ с VLM, около 6 ГБ без неё (`VLM_CONFIRM=0`).
  Без CUDA VLM выключается сама.
- **Интерфейс** в compose не входит и поднимается отдельно
  (`npm run dev --prefix web`).

## Ограничения

- **Позиции без эталона.** 12 из 2103 не находятся ни при каких условиях.
- **Почти-дубли.** Часть позиций одной линейки различается крепостью или
  годом, которых нет на лицевой этикетке.
- **Карточки-дубли.** 159 карточек в 72 группах с одинаковыми винодельней
  и названием, часто с эталонами разных тиражей. Какой slug ожидает
  закрытая разметка, неизвестно.
- **Слабые эталоны.** У части линеек эталоны — мелкие скриншоты или
  этикетка прошлого поколения. Геометрии на них мало точек, и решают
  косинус, текст и VLM.
- **Вина вне каталога, в которых VLM сомневается.** Если соседа по
  линейке VLM не отвергает явно (P(yes) от 0.05), он показывается с
  оговоркой: «Сухое розовое» Перовских против «Полусладкого розового»
  (0.5), рукописные названия, которые не читает OCR.
- **Время ответа.** На снимке телефона 3024×4032 медиана ответа 1.3 с. Когда VLM проверяет нескольких кандидатов подряд и читает этикетку
  (отказы и отвергнутые в полосе «скорее всего»), — до 5.5 с; на снимках
  организатора дольше 3 с отвечают 31 из 97. `LABEL_RESCUE_BUDGET_MS` и
