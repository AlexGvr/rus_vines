# PWA «Своё Вино» (app/)

Offline-first веб-приложение: скан этикетки → OCR в браузере → поиск по локальной базе 2017 вин. Работает целиком без сети после первой загрузки. Бандл ~32 МБ.

## Структура файлов

```
app/
├── index.html              разметка: три таба, оверлей карточки, подключение Tesseract и app.js
├── manifest.webmanifest    PWA-манифест (standalone, ru, icon.svg)
├── icon.svg                иконка приложения
├── sw.js                   service worker: precache + стратегии кэширования
├── css/style.css           все стили (~7 КБ)
├── js/
│   ├── app.js              загрузка датапака, табы, каталог, карточка, localStorage
│   ├── scan.js             скан-пайплайн: подготовка кадров, OCR, вывод результатов
│   ├── matcher.js          матчер (зеркало core/matcher.py, см. docs по ядру)
│   └── normalize.js        канонизация текста (зеркало core/normalize.py)
├── data/wines.json         датапак: 2017 вин + meta {version, hash, count} (2.2 МБ)
├── photos/                 2017 webp 400px, ~10 КБ каждое (18 МБ)
└── vendor/tesseract/       Tesseract.js целиком локально (12 МБ)
    ├── tesseract.min.js, worker.min.js
    ├── tesseract-core-simd-lstm.wasm.js, tesseract-core-lstm.wasm.js
    └── lang/rus.traineddata.gz, eng.traineddata.gz
```

Никакого бандлера и зависимостей: ES-модули, ванильный JS, деплой — раздача статики.

## Три таба и UX-потоки

- **Скан** (стартовый): большая круглая кнопка → системная камера/галерея → прогресс-бар с превью и статусами («Готовлю фото…» → «Читаю этикетку… N%» → «Ищу в базе…») → результаты. Клик по результату пишет запись в историю и открывает карточку.
- **Каталог**: живой поиск через тот же матчер (релевантность), чипы цвета (мультивыбор), селекты категория/регион/сорт (заполняются из данных), сортировка по рейтингу при пустом запросе, инфинит-скролл порциями по 40 через `IntersectionObserver`.
- **Мои вина**: избранное (♥ на карточке) + история сканов (последние 50 на экране, с датой и временем; confidence хранится в записи, в списке не отображается).
- **Карточка вина** — полноэкранный оверлей `#detail` поверх любого таба: фото, факты-теги (категория, цвет, алкоголь, температура подачи, сорта), описание, «к блюдам», личная оценка 1–5 звёзд (сохранение по клику) и текстовая заметка (сохранение на `change`).

## Скан-пайплайн

Код: [app/js/scan.js](../app/js/scan.js).

1. **Захват**: `<input type="file" accept="image/*" capture="environment">` — на телефоне открывает камеру, на десктопе — выбор файла.
2. **`prepImages()` — два кадра** из одного фото через `createImageBitmap` + canvas: полный кадр и кроп зоны этикетки (x 18%, y 38%, ширина 64%, высота 50% кадра — рассчитан на фото бутылки целиком). Оба: grayscale + contrast 1.3, апскейл/даунскейл до 1400px по длинной стороне (кратность апскейла ≤4). Геометрия кропа зеркалится в [core/eval.mjs](../core/eval.mjs) — менять синхронно.
3. **OCR**: один переиспользуемый воркер `Tesseract.createWorker("rus+eng", 1, ...)` — все пути (`workerPath`, `corePath`, `langPath`) указывают в `vendor/tesseract/`, сеть не нужна. Ленивая инициализация при первом скане, прогресс из `logger` идёт в прогресс-бар. Два последовательных `recognize` (полный кадр, затем кроп) — двухпроходность подняла top-1 на eval с 16 до 23.3%.
4. **Матчинг**: тексты обоих проходов конкатенируются и уходят в `state.matcher.search(text, 5)`.
5. **Бейджи уверенности** (`confBadge`): conf ≥ 0.45 — зелёный; ≥ 0.22 — жёлтый, заголовок «Похоже, это…»; ниже — «Уверенности мало — проверьте варианты» и топ-5. Пустой результат — подсказка переснять ближе и при хорошем свете.

## Офлайн-архитектура

Код: [app/sw.js](../app/sw.js). Версия кэша — константа `VERSION` ("v1"), два кэша: `shell-{VERSION}` и `photos-{VERSION}`. На `activate` все кэши с другими именами удаляются — bump `VERSION` инвалидирует всё разом.

- **Precache** (`install`): 16 записей — shell (html, manifest, icon, css, 4 js-модуля), `data/wines.json` и весь Tesseract-стек включая оба wasm и оба языка. После первой загрузки скан работает полностью офлайн.
- **`data/wines.json` — network-first**: при сети тянется свежий датапак и кладётся в кэш, офлайн — отдаётся кэш. Обновление базы не требует новой версии SW.
- **`photos/*` — cache-on-demand**: 18 МБ фото не входят в precache; каждое фото кэшируется в `photos-v1` при первом показе (lazy-load в списках).
- **Всё остальное — cache-first** с `ignoreSearch`, фолбэк в сеть.
- Кросс-доменные запросы SW не трогает (`url.origin !== location.origin`) — их и нет.

### Установка на телефон

Приложение раздаётся по HTTPS (или localhost), манифест — `display: standalone`. Android/Chrome: меню → «Добавить на главный экран» (или системный промпт установки). iOS/Safari: Поделиться → «На экран "Домой"». После установки открывается без браузерного хрома, иконка и заставка — из манифеста.

### Ограничение iOS Safari — и почему Flutter надёжнее

- Safari **выселяет весь storage** (Cache Storage, localStorage) сайта примерно после **7 дней без использования** (ITP). Для PWA, добавленной на экран «Домой», счётчик мягче, но гарантий нет: пользователь, не открывавший приложение пару недель, рискует получить повторную загрузку 32 МБ — и потерю истории/заметок из localStorage.
- Квоты Cache Storage на iOS ограничены и непрозрачны; при давлении на диск кэш вычищается без предупреждения.
- Нет доступа к нативному OCR (Apple Vision), Tesseract-wasm медленнее и тяжелее.

Flutter-приложение ([mobile/](../mobile/)) свободно от всего этого: ассеты в APK/IPA не выселяются, данные — в shared_preferences, OCR — нативный (ML Kit / Apple Vision). PWA — канал мгновенной дистрибуции и демо, Flutter — надёжная поставка.

## Хранение пользовательских данных

Всё в `localStorage` (JSON через обёртку `store` в [app/js/app.js](../app/js/app.js)):

| Ключ | Формат | Ограничения |
|---|---|---|
| `history` | `[{slug, confidence, ts}]` | хранится 200 последних (`slice(0, 200)`), на экране 50 |
| `favs` | `[slug]` | новые в начало |
| `notes` | `{slug: {rating?, note?}}` | звёзды 1–5 + текст |

Синхронизации нет; очистка данных сайта (или iOS-выселение) стирает всё.

## Локальная разработка

```bash
cd app && python3 -m http.server 8080
# http://localhost:8080
```

Сервер не нужен ни для чего, кроме раздачи статики (ES-модули и SW не работают с file://).

**Ловушка SW-кэша**: после первого визита `sw.js` отдаёт js/css/html из `shell-v1` cache-first — правки кода «не применяются». Как сбросить:

- DevTools → Application → Service Workers → включить **«Update on reload»** (+ галка Bypass for network) — на время разработки;
- либо Application → Storage → **Clear site data**;
- либо поднять `VERSION` в [app/sw.js](../app/sw.js) — старые кэши снесутся на `activate` (это же — штатный путь релиза новой версии shell);
- радикально — временно закомментировать `navigator.serviceWorker.register("sw.js")` в конце `boot()` в app.js.

`data/wines.json` под network-first, поэтому пересборка датапака (`etl/build_datapack.py`) видна по обычному reload без сброса SW.

## Размер бандла по частям

| Часть | Размер | Комментарий |
|---|---|---|
| `photos/` | 18 МБ | 2017 webp 400px, ~10 КБ/шт; не в precache, кэш по требованию |
| `vendor/tesseract/` | 12 МБ | 2 wasm-ядра по 3.8 МБ (SIMD + фолбэк), lang 3.5 МБ (eng 1.9 + rus 1.6) |
| `data/wines.json` | 2.2 МБ | 2017 вин, версия+hash в meta |
| `js/` + `css/` | ~27 КБ | собственный код, без бандлера |
| **Итого** | **~32 МБ** | первая офлайн-готовность (precache) — ~14 МБ без фото |

Резервы: выкинуть не-SIMD ядро (−3.8 МБ, SIMD есть во всех актуальных браузерах), gzip/brotli на wines.json при раздаче (~4–5× сжатие).
