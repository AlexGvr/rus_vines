# Ядро распознавания

> **Архив.** Документ описывает первый офлайн-MVP (OCR-поиск по тексту,
> `app/`, `mobile/`), от которого сервис ушёл к поиску по изображению.
> Из него в работе остались `core/matcher.py` и `core/normalize.py` —
> нечёткое сравнение токенов в текстовом канале (`pipeline/text_match.py`). Текущая архитектура и замеры —
> [ARCHITECTURE.md](../ARCHITECTURE.md) и [metrics.md](metrics.md).

## Постановка задачи

Вход — шумный текст с этикетки после OCR: смесь кириллицы и латиницы, битые буквы, обрывки слов, проценты, ГОСТы. Выход — ранжированный список карточек из базы 2017 вин с оценкой уверенности 0..1. Это не полнотекстовый поиск, а сопоставление «мешка токенов» с карточками: порядок слов не важен, каждый токен запроса ищет себе лучшее совпадение в документе.

Референс ядра — [core/normalize.py](../core/normalize.py) + [core/matcher.py](../core/matcher.py); боевые зеркала — [app/js/](../app/js/) (PWA) и [mobile/lib/core/](../mobile/lib/core/) (Flutter). Поиск по всей базе ~66 мс (JS).

## Нормализация

Каноническое пространство — **кириллица в нижнем регистре**. Этикетки российских вин пишут бренды как угодно (Aristov / АРИСТОВ / Fanagoria / Фанагория), поэтому все латинские токены приводятся к кириллице жадным диграфным транслитом `LAT2CYR` (сначала длинные диграфы: `shch→щ`, `zh→ж`, `kh→х`, `ch→ч`, `ts→ц`, `qu→кв`, `ph→ф`…, затем одиночные буквы).

Примеры:

- `ARISTOV` → `аристов` — точное совпадение с токеном базы.
- `riesling` → `риеслинг` — транслит не совпадает с базовым `рислинг` буква в букву, но добирается фаззи-матчем: длина 8, Левенштейн 1 ≤ 2 → вклад 0.7. Транслиту не нужно быть идеальным — достаточно попасть в радиус фаззи.

Чистка перед токенизацией ([clean](../core/normalize.py)): `İ→I` (до lowercase, см. «Ограничения»), `ё→е`, кавычки-ёлочки → пробел, всё кроме `[a-zа-я0-9]` → пробел. Токены короче 2 символов отбрасываются.

**Стоп-слова — только шумовые**: `вино`, `wine`, `россия`, `ооо`, `гост`, `алк`, `vol`, `урожай`… Категорийные слова (`брют`, `белое`, `сухое`) стоп-словами **не являются** — намеренно. Кейс «Граф Воронцов брют белое»: у бренда линейка из нескольких вин, и различают их именно `брют`/`белое`/`розовое`. У вин таких линеек эти слова обычно входят в сам title («Граф Воронцов. Брют белое»), а вес токена берётся как максимум по полям — то есть 3.0; для карточек без категорийного слова в названии остаётся поле категории с весом 0.5. Частотность в обоих случаях гасится IDF, и внутри линейки одного бренда эти токены дают решающий перевес нужной карточке.

## Алгоритм матчера

Индексация ([Matcher.\_\_init\_\_](../core/matcher.py)): для каждой карточки токенизируются поля и каждому токену присваивается вес поля (при повторе токена в разных полях — максимум):

| Поле | Вес |
|---|---|
| title | 3.0 |
| manufacturer | 2.0 |
| grapes | 1.0 |
| region + category (`extra`) | 0.5 |

IDF по документной частоте `df` при `n = 2017`:

```
idf(t) = 0.5 + ln(n / df(t)) / ln(n)
```

Диапазон ~0.5 (токен есть везде) … 1.5 (токен уникален). Редкие токены (бренды) доминируют, частые (`полусладкое`) лишь доуточняют.

Совпадение пары токенов `tokens_match(q, d)`:

- `1.0` — точное равенство;
- `0.85` — один префикс другого, `len(q) ≥ 4`, разница длин ≤ 3 (OCR режет окончания);
- `0.7` — Левенштейн ≤ 1 при `max(len) ≥ 5` или ≤ 2 при `max(len) ≥ 8` (OCR путает буквы);
- `0.0` — иначе.

Скор документа: каждый токен запроса берёт лучшее совпадение по документу, дубли токенов запроса схлопываются (`set`):

```
score = Σ_q max_d ( match(q, d) × weight(d) × idf(q) )
confidence = score / (Σ_q idf(q) × 3.0)
```

Знаменатель — идеальный случай «все токены запроса точно совпали с title», так что confidence ∈ 0..1. Шум OCR (нераспознанные обрывки) честно давит confidence вниз — это фича: мусорный скан не даст ложной уверенности.

Финальные штрихи: год из запроса, совпавший с годом в title/slug карточки, — бонус `+0.1` (cap 1.0); отсечка `confidence > 0.02`; tie-break при равном confidence — по `rating` карточки по убыванию.

## Пороги UI и деградация

Пороги в [app/js/scan.js](../app/js/scan.js):

Список топ-5 совпадений показывается всегда; пороги управляют заголовком и цветом бейджей:

- `conf ≥ 0.22` — заголовок «Похоже, это…»; бейдж зелёный при ≥ 0.45, жёлтый при 0.22–0.45;
- `conf < 0.22` — заголовок «Уверенности мало — проверьте варианты», бейджи красные — пользователь выбирает глазами. Деградация мягкая: даже слабый OCR обычно затаскивает истину в топ-5 (см. eval).

## OCR-движки по платформам

| | PWA ([app/js/scan.js](../app/js/scan.js)) | Mobile ([mobile/lib/services/ocr_service.dart](../mobile/lib/services/ocr_service.dart)) |
|---|---|---|
| Движок | Tesseract.js `rus+eng`, в бандле (vendor 12MB) | ML Kit text recognition, **latin script** |
| Кириллица | да, нативно | **нет** — у ML Kit нет кириллической модели; кириллица частично читается как латиница и компенсируется транслитом `LAT2CYR` |
| Препроцессинг | два прохода: полный кадр + кроп зоны этикетки (18% / 38% / 64%×50%), grayscale + contrast 1.3, таргет 1400px | кадр как есть с камеры/галереи |
| Скорость | секунды (WASM) | десятки мс (нативный) |
| Прод-путь | как есть | Apple Vision на iOS / Tesseract FFI / серверный fallback (Qwen2.5-VL, спроектирован, не реализован) |

Двухпроходный кроп в PWA — главный выигрыш на фото полной бутылки: этикетка занимает малую долю кадра, кроп центральной зоны поднимает разрешение текста для Tesseract.

## Методика eval и цифры

[core/eval.mjs](../core/eval.mjs): тот же стек, что в PWA (Tesseract.js `rus+eng`, двухпроходный кроп через sharp), 150 детерминированно выбранных (seed 42) эталонных фото 1200px, кэш в `data/eval_photos/`. Запуск: `node core/eval.mjs [N]`.

Результат: **top-1 23.3%, top-5 38.0%**.

Честная оговорка: это **худший кейс** — эталонные фото каталога снимают полную бутылку, этикетка мелкая, стекло бликует. Двухпроходный кроп поднял top-1 с 16% до 23.3%; PSM 11 выигрыша не дал. Прицельные фото этикетки крупным планом читаются радикально лучше (в живом тесте бренд + категория дают conf 1.0). Eval — нижняя граница и регрессионный якорь для правок ядра, а не прогноз боевого качества.

## Три зеркала и golden-паритет

Ядро существует в трёх синхронных копиях:

1. Python-референс: [core/normalize.py](../core/normalize.py), [core/matcher.py](../core/matcher.py);
2. JS (PWA): [app/js/normalize.js](../app/js/normalize.js), [app/js/matcher.js](../app/js/matcher.js);
3. Dart (mobile): [mobile/lib/core/normalize.dart](../mobile/lib/core/normalize.dart), [mobile/lib/core/matcher.dart](../mobile/lib/core/matcher.dart).

Паритет JS ↔ Dart фиксируется golden-эталоном: [tools/gen_golden.mjs](../tools/gen_golden.mjs) прогоняет через JS-ядро 30 запросов (плюс контрольные точки транслита, токенизации и извлечения годов) и пишет `mobile/test/golden_parity.json`; [mobile/test/parity_test.dart](../mobile/test/parity_test.dart) сверяет Dart-порт с точностью 1e-4 по confidence.

Процедура при любой правке ядра или датапака:

```
# 1. править синхронно все три зеркала
# 2. из корня репо:
node tools/gen_golden.mjs
cd mobile && flutter test test/parity_test.dart
```

## Известные ограничения

- **'İ' (U+0130)**: турецкая İ встречается в OCR-мусоре; full и simple case mapping для неё расходятся между рантаймами (JS/Python/Dart дают разный lowercase). Унифицировано `replaceAll('İ','I')` **до** lowercase во всех трёх зеркалах — при портировании на новую платформу это правило обязательно.
- **Линейки одного бренда**: вина, различающиеся только категорийным словом или сортом (`… брют белое` vs `… брют розовое`), разводятся категорийными токенами (вес 3.0, если слово входит в title, иначе 0.5 полем категории); если OCR не прочёл различающее слово, матчер отдаёт tie-break по рейтингу и может выбрать соседа по линейке. Миллезимы одного вина различаются только год-бонусом +0.1.
- **Нечитаемые этикетки**: рукописные/декоративные шрифты, тиснение фольгой, блик по стеклу — OCR возвращает пусто или мусор, confidence падает под 0.22, UI честно деградирует в топ-5 или «не распознано». Для этих случаев спроектирован серверный fallback (Qwen2.5-VL), пока не реализован.
- Транслит жадный и однопроходный: экзотические написания (`x`, `w`, французские диакритики после чистки) дают приближённую кириллицу и опираются на фаззи-порог Левенштейна — токены короче 5 символов фаззи не покрываются.
