# Аудит оставшихся ошибок final3, 2026-09-22

Проверены реальные выбранные конвейером кропы всех 20 ошибок tune. Рабочий код, индекс, манифест и пороги не изменены. GEOM_WEIGHT=0. Исходные транскрипции сохранены; новая версия — data/field/transcripts_final3_audited.json.

## Измеренный результат

На 12 ошибках лицевых кадров с эталоном ручное чтение при текущем ранжировании исправляет 4: Brûlé (ir_ochen-vkusnoe-legkoe-vino-dlya-semeinogo_0.jpg), красное полусладкое Абрау (13978352_0.jpg), Портвейн белый крымский (15598335_0.jpg), розовое полусухое Абрау (16151511_0.jpg). Это четыре разных SKU.

Обычный OCR в повторном прогоне даёт те же лидеры, что final3, на всех 20 кадрах. Если подменить текст только в этих четырёх ошибках, арифметический результат был бы 138/154 = 89,6% вместо 134/154 = 87,0%. Это диагностический сценарий с известными ошибками, НЕ измеренная точность нового OCR на всей выборке.

Контроль прежних транскрипций на текущем индексе: 22 доступных кадра, 21 findable; OCR 11 верных, ручной текст 14, три исправления, ноль испорченных. Все 11 ранее правильных findable-кадров остаются правильными. Это небольшой выбранный контроль, не доказательство отсутствия регрессий на всём наборе. Четвёртый исправляемый случай — новая транскрипция 16151511_0.jpg.

## Причины оставшихся ошибок

- Два случая с читаемым текстом и ограничением сопоставления. Victor Dravigny (12083971_0.jpg): «ПОЛУСЛАДКОЕ» исключает брют, но оставляет красное полусладкое выше нужного белого. Диагностический DEMOTE_GEOMETRY=1 с ручным текстом возвращает верный ответ. «Олег» (org091_0.jpg): слово одновременно стоит в title и grapes и вычитается из CardFeatures.name; множество name пустое. Дополнительно name_slugs требует минимум пять букв. Это не основание исправлять каталог: название может совпадать с сортом. Реальный OCR выдаёт «ОХЕГ», поэтому поддержка точного имени сама по себе не исправит реальный кадр.
- Один смешанный случай (6182553_0.jpg): читается «РОЗОВОЕ», сладость не читается достаточно уверенно и в новую транскрипцию не внесена. Отбраковка останавливается после четырёх кандидатов. Продолжение до depth=20 всё равно выбирает другое розовое вино. Нельзя записывать этот случай в гарантированно исправимые изменением глубины.
- Пять случаев без достаточного различающего текста: 15501518_0.jpg (цвет не читается уверенно), 13918558_1.jpg (название за границей кадра), 16151511_1.jpg (мелкая строка не читается уверенно), 17762210_0.jpg (два ZB Frizzante, на лицевой этикетке нет сортов для строгого выбора карточки), 6310320_0.jpg (старый Brut d’Or 2010, сорта, различающего текущие карточки, не видно). Это ограничение текстового канала, а не доказательство невозможности различения любым визуальным методом.
- Семь контрэтикеток/боковых кадров остаются в основном знаменателе. Для них внесены видимые идентифицирующие строки, а не полный юридический текст. В пяти из семи правильного SKU нет в текущем top-20: 11406313_1, 13795944_1, 15598335_1, 6522615_1, 7193178_1. Замена OCR после retrieval не может его добавить; нужен отдельно оцениваемый поиск по тексту каталога, если такие ракурсы входят в приёмку.
- 7579301_0.jpg: нет индексированного эталона. Видимое ABRAU не определяет точный SKU.

Автоматические diagnosis в eval_transcript перечисляют различия карточек, но не устанавливают, видны ли эти различия на фото. Для выводов использована ручная классификация выше.

## Что делать следующим

1. Проверить чтение различающих строк на четырёх OCR-исправимых кадрах плюс правильных контрольных кадрах. Измерять конечный top-1, новые ошибки и задержку. Не повторять только увеличение всей картинки: прежний такой эксперимент уже не помог. Кандидат для проверки — отдельное обнаружение/чтение мелкой и наклонной строки с ограничением областью целевой бутылки.
2. Отдельный эксперимент сопоставления для названий, совпадающих с сортом: учитывать совместное свидетельство производителя и названия/сорта, не снижать глобально пороги для всех коротких слов. Не добавлять исключение по slug oleg и не включать нечёткий ОХЕГ→ОЛЕГ без проверки отрицательных примеров.
3. Повторный выбор геометрией после надёжного текстового противоречия имеет один подтверждённый здесь диагностический выигрыш. Глобальный флаг ранее не прошёл проверку; включать его по умолчанию на основании одного случая нельзя.
4. Для семи боковых/обратных кадров оценивать отдельный текстовый retrieval; для неполных кадров и отсутствующих эталонов продолжать работу с данными. Закрытая приёмочная выборка по-прежнему необходима.

## Воспроизведение

Из корня репозитория, тяжёлые прогоны последовательно:

```bash

HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 GEOM_WEIGHT=0 .venv/bin/python pipeline/eval_transcript.py --transcripts /home/alex/projects/rus_vines/data/field/transcripts_tune.json --output data/validation/transcript_final3_legacy_control.json
GEOM_WEIGHT=0 .venv/bin/python data/validation/transcript_final3_assets/trace_rules.py
```

trace_rules.py использует сохранённые final3 геометрические оценки для трёх диагностических случаев, чтобы не примешивать случайность повторной оценки RANSAC. Это трассировка причин, не полный прогон сервиса.

Артефакты: transcript_final3_audited.json, transcript_final3_legacy_control.json, transcript_final3_rule_trace.json, transcript_final3_audit_summary.json. Кропы и обзорные листы: transcript_final3_assets/. Начальный прогон с относительным путём транскрипций упал при сохранении provenance; повтор с абсолютным путём завершён успешно.
