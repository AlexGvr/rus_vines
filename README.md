# Сканер российских вин «Своё Вино»

Фотография этикетки — карточка вина из каталога платформы «Своё Вино».
Кейс РСХБ.Цифра 2026.

Поиск трёхступенчатый: SigLIP 2 отбирает двадцать кандидатов по каталогу
(кадр идёт двумя видами — целиком и кропом по бутылке), локальные признаки
решают, какой из них та же самая этикетка, а если они не развели лидеров —
читается сама этикетка. Детали и обоснование решений —
в [ARCHITECTURE.md](ARCHITECTURE.md).

## Результаты

Главная метрика — строгий top-1 по slug на 100 фотографиях организатора
из публичного набора кейса («Реальные фото»: съёмка телефоном у полки,
3024×4032; 97 размечены по надписям на этикетке, 3 спорных в счёт не идут;
треть — вина вне каталога). По рекомендации организатора решение опирается
только на изображения из датасета кейса: эталоны — фото из дампа, калибровка
и пороги — синтетика из эталонов дампа и настроечная часть этих кадров.
Методика и история замеров — в [docs/metrics.md](docs/metrics.md).

| 100 снимков организатора | настроечная часть | регрессионная часть | все |
|---|---|---|---|
| вин каталога / вне каталога | 33 / 21 | 29 / 14 | 62 / 35 |
| строгий top-1 по винам каталога | **26 из 33 (78.8%)** | **27 из 29 (93.1%)** | **53 из 62 (85.5%)** |
| top-3 / top-5 | 84.8% / 84.8% | 96.6% / 96.6% | 90.3% / 90.3% |
| F1 top-1 / top-5 с отказом (порог 0.10) | 76.7% / 80.0% | 86.7% / 90.0% | 81.7% / 85.0% |
| карточка показана вину вне каталога | 2 из 21 | 4 из 14 | 6 из 35 |
| `/v1/eval/predict`, если пустой ответ верен для вина вне каталога | 46 из 54 | 36 из 43 | **82 из 97** |
| `/v1/eval/predict`, если пустой ответ не засчитывается | 27 из 54 | 26 из 43 | 53 из 97 |

Настроечная часть ниже регрессионной: 12 кадров, размеченных последними,
ушли в неё уже после подбора порогов, и среди них четыре промаха.
Строки конвейера — `pipeline/organizer_summary.py`
(`data/validation/organizer100_20260925.json`), строки `/v1/eval/predict` —
сквозной прогон через HTTP в режиме по умолчанию
(`data/validation/api_geo_fallback_all_20260926.json`).

Синтетический набор из эталонов дампа (214 отложенных запросов с вином
в каталоге): F1 top-1 89.3%, F1 top-5 94.7% — это блок `quality` в ответах
и в `/health`, рядом блок `field` с числами регрессионной части.

Полный путь через HTTP в режиме по умолчанию (`pipeline/api_check.py`,
все 402 кадра): на 97 снимках организатора 3024×4032 медиана ответа 928 мс,
p95 3058 мс, максимум 3360 мс, дольше 3000 мс — 5 кадров; на всех 402 —
медиана 591 мс, p95 2183 мс. Дольше всего отвечают кадры, где VLM
проверяет несколько кандидатов подряд; `VLM_BUDGET_MS=2000` держит все
ответы в 3 с ценой одного верного ответа (docs/metrics.md).

Как закрытая таблица засчитывает вино вне каталога, организатор не сообщил
(`docs/organizer_questions.md`), поэтому `/v1/eval/predict` по умолчанию
отказывается отвечать (`{"slug": null}`) ниже порога показа, если ответ
не подтвердил VLM. На 97 кадрах это 53 → 82 верных, если пустой ответ
засчитывается, и 53 → 53, если нет. `EVAL_ABSTAIN=0` возвращает ответ
«всегда лучший кандидат».

Регрессионная часть уже использовалась при разборе ошибок и не является
независимым holdout; для подтверждения приёмки нужна новая закрытая
съёмка (протокол в docs/metrics.md). Части делятся связными группами
«вино — фотосерия»; калибровка, пороги и правила выбора подбирались
только на настроечной.

Что осталось на 62 винах каталога — девять промахов:

- четыре — «Табия»: «Цитрон» дважды, «Олег», «Рубин Голодриги». SigLIP
  ставит их первыми, но эталоны всей линейки в дампе — скриншоты около
  290×556, и по точкам этикетки соседи по линейке не различаются;
- два кадра «Заката» Денисова — у позиции нет эталона в датасете;
- три — соседи по линейке: «Мускатель белый» против «Муската. Авторское
  вино», «Formula Q» Каберне Совиньон против Саперави, «Поздний сбор»
  белое против красного.

В ответе сервиса «Олега» и один из «Цитронов» исправляет VLM-арбитр
(`VLM_FALLBACK`, `VLM_CONTRA`): при отказе он проверяет ещё двух
кандидатов, а при уверенно прочитанном слове чужой карточки — лидера и
владельцев слова. На 402 кадрах через HTTP +5 верных, потерь нет.

С эталонами с товарных страниц на прежних 93 кадрах было 58 из 62
вместо 56 — разница целиком на позициях, где эталона в дампе нет или он
устарел (docs/metrics.md). Что проверено и не подтвердилось: VLM как
переранжировщик пятёрки, DINOv2 как второй канал отбора, текстовый признак
«прочитана чужая винодельня» (2026-09-23); сопоставление SIFT один
к одному и защита лидера по косинусу против промахов «Табии»; внешний
датасет WineSensed (2026-09-25) — docs/metrics.md.

## Требования

- Python 3.12, около 13 ГБ свободной видеопамяти с подтверждением VLM
  (по умолчанию) или около 6 ГБ без него (`VLM_CONFIRM=0`); проверялось на
  RTX 5060 Ti 16 ГБ. Сервис работает и на процессоре, но медленнее: снимок
  телефона 3024×4032 — около 10 с, подтверждение VLM на процессоре
  не включается.
- Node.js 20+ — только для интерфейса.
- Около 5 ГБ на диске под каталог, индексы и веса моделей.
- Данные кейса: `strapi_output0709.csv` и дамп Strapi с фотографиями.

## Запуск

### 1. Данные

Распакуйте дамп кейса так, чтобы получилось:

```
dataset/
  strapi_output0709.csv
  uploads_root/**/strapi/uploads/*.webp
  eval/                      # публичный датасет со скриптом оценки
```

Многотомный RAR распаковывается штатным `unrar x prod-svoe-vino-strapi.part1.rar`.

### 2. Окружение

```bash
python3 -m venv .venv
.venv/bin/pip install --index-url https://download.pytorch.org/whl/cu128 torch torchvision
.venv/bin/pip install transformers ultralytics opencv-python-headless \
    fastapi uvicorn python-multipart pillow numpy easyocr
```

Без видеокарты замените индекс на `https://download.pytorch.org/whl/cpu`.

### 3. Сборка каталога и индексов

Точная привязка фотографий к позициям лежит в репозитории
(`data/datapack/photo_map.csv`), поэтому каталог собирается одинаково на
любой машине. Пересобрать привязку из свежего обхода платформы — флагом
`--refresh-map`, но для запуска это не нужно.

Сервис использует только изображения из датасета кейса (рекомендация
организатора): эталон позиции — файл из дампа Strapi, других фотографий
в индексе нет. Механизм дополнительных эталонов (`data/catalog/extra_refs.csv`)
и сверка с каталогом платформы (`pipeline/sync_platform.py`) остались в
коде как проверенные замером приёмы, но в сдаваемой версии не используются:
список пуст, дополнений нет.

Ручные исправления привязки — `data/datapack/photo_overrides.csv`:
зафиксированные пробелы — позиции, у которых в дампе нет файла эталона
или файл из CSV показывает другое вино. Такая позиция остаётся без
эталона, а не получает чужое фото. Исправления применяются при сборке
последними и переживают пересборку каталога.

```bash
.venv/bin/python pipeline/build_catalog.py       # каталог + привязка фото
.venv/bin/python pipeline/build_index.py --variant clean --views raw,detect --name clean_mv
.venv/bin/python pipeline/build_rerank_index.py  # признаки эталонов
```

Первый запуск скачает веса SigLIP 2 (около 3.5 ГБ), YOLO11m и
Qwen3-VL-4B-Instruct (около 9 ГБ, для подтверждения ответа).

### 4. Сервис

```bash
.venv/bin/python -m uvicorn service.main:app --host 127.0.0.1 --port 8080
curl http://127.0.0.1:8080/health
```

### 5. Интерфейс

```bash
npm install --prefix web
npm run dev --prefix web        # http://localhost:3300
```

С телефона в той же сети Wi-Fi: запустите API с `--host 0.0.0.0`,
интерфейс — `npm run dev --prefix web -- --host 0.0.0.0 --port 3300` и
откройте `http://<IP компьютера>:3300`. Адрес API интерфейс берёт из адреса
страницы, кнопка «Сканировать этикетку» открывает камеру телефона.
Фото карточки увеличивается по касанию; варианты и похожие вина ведут на
страницу вина (`/wine/<slug>`), «Назад» возвращает к результату.

### Через Docker

```bash
docker compose up --build
```

Для доступа к видеокарте нужен `nvidia-container-toolkit`. Без него уберите
секцию `deploy.resources` из `docker-compose.yml` и соберите процессорный
вариант:

```bash
TORCH_INDEX=https://download.pytorch.org/whl/cpu docker compose up --build
```

Каталог, индексы и дамп монтируются в контейнер из репозитория, веса моделей
кэшируются в томе `hf-cache` — пересборка образа их не теряет. Первый старт
скачивает около 13 ГБ весов и занимает до десяти минут.

Проверено 2026-09-26 на RTX 5060 Ti (`nvidia-container-toolkit`, Docker
Compose v2): через `docker compose up` ответы совпали с сервисом вне
контейнера на всех 402 кадрах, на снимках организатора медиана ответа
1057 мс, p95 3172 мс (`data/validation/api_docker_gpu_all_20260926.json`).

В compose сервис хранит векторы индекса и карточки в PostgreSQL с pgvector
(сервис `db`, как рекомендует ТЗ): при старте индекс из `data/index`
загружается в базу и перезагружается после пересборки (сверка по хешу).
Поиск точный, шортлисты совпадают с numpy-вариантом на всех 390 кадрах
полевого набора (`python pipeline/vector_store.py --check`). Без compose
сервис по умолчанию держит индекс в памяти (`VECTOR_BACKEND=numpy`).

## Проверка

Скрипт оценки кейсодержателя:

```bash
cd dataset/eval
./participant_test.sh --images-dir ./queries --manifest ./queries.tsv \
  --endpoint 'http://127.0.0.1:8080/v1/eval/predict' --output ./predictions.jsonl
```

Собственные метрики:

```bash
bash pipeline/harness.sh                                    # скрипт кейса + точность
.venv/bin/python pipeline/report.py --subset sharp --held-out  # F1 топ-1 и топ-5
.venv/bin/python pipeline/eval_field.py                     # полевой набор
.venv/bin/python pipeline/eval_rerank.py --subset sharp --topk 20 \
    --index clean_mv --views raw,detect
.venv/bin/python pipeline/calibrate.py --subset sharp           # пороги выдачи
.venv/bin/python pipeline/bench_latency.py --count 50        # время ответа
```

Разбор и сравнение прогонов полевого набора:

```bash
.venv/bin/python pipeline/eval_field.py --split tune --candidate-features \
    --output data/validation/run.json            # прогон с кандидатами и OCR
.venv/bin/python pipeline/analyze_misses.py data/validation/run.json --verbose
.venv/bin/python pipeline/compare_runs.py data/validation/before.json \
    data/validation/after.json --titles          # парное сравнение двух прогонов
.venv/bin/python pipeline/api_check.py --split test  # полный путь через HTTP
```

Два прогона на одной видеокарте одновременно запускать нельзя: EasyOCR
падает по памяти, кадр идёт дальше без текста, и прогон перестаёт быть
парным. Теперь такой отказ считается и печатается в конце прогона.

Валидационные наборы собираются заранее:

```bash
.venv/bin/python pipeline/make_queries.py --hard --name sharp --count 400 \
    --min-side 1500 --canvas 1350x1800
.venv/bin/python pipeline/make_queries.py --hard --name neardup --count 200 \
    --repeats 3 --min-side 1500 --only-neardup --canvas 1350x1800 --seed 5
```

## API

| метод | путь | назначение |
|---|---|---|
| `POST` | `/v1/eval/predict` | контракт скрипта оценки: поле `image`, ответ `{"slug": "..."}` |
| `POST` | `/v1/search` | полный ответ: карточка, уверенность, варианты, тайминги |
| `GET` | `/v1/wines/{slug}` | карточка, гастропары, аналоги других виноделен |
| `GET` | `/v1/sommelier/questions` | вопросы «Цифрового сомелье» |
| `POST` | `/v1/sommelier` | подбор по ответам |
| `GET` | `/v1/photo/{slug}` | эталонное фото позиции |
| `GET` | `/health` | состояние модели и индекса |

Ответ `/v1/search` различает три состояния: `confident` — одна карточка,
`uncertain` — карточка с признанием сомнения и вариантами, `unsure` —
уверенно определить не удалось, показываем ближайшее по виду. Решает
совместная оценка по отрыву кандидатов, числу совпавших точек, визуальной
близости и раскладке совпадений; веса и пороги — в
`data/index/calibration_sharp.json`, обучение и проверка в
`pipeline/calibrate.py`.

Эндпоинт оценки по умолчанию порог не применяет и отдаёт лучший ответ.
Как закрытая таблица оценивает вино вне каталога, организатор не сообщил,
а в его публичном наборе таких кадров треть; если пустой slug для них
засчитывается, отказ включается `EVAL_ABSTAIN=1` (расчёт обоих правил —
`pipeline/eval_scoring.py`, вопросы — `docs/organizer_questions.md`).

## Переменные окружения

| переменная | по умолчанию | назначение |
|---|---|---|
| `YOLO_WEIGHTS` | `yolo11m.pt` | путь к весам детектора |
| `HF_HOME` | `~/.cache/huggingface` | кэш весов SigLIP |
| `NUXT_PUBLIC_API_BASE` | тот же хост, что у страницы, порт 8080 | адрес API для интерфейса |
| `TORCH_INDEX` | `.../whl/cu128` | индекс сборки torch при сборке образа |
| `SHOW_P` | из `confidence.json` (0.10) | ниже этой уверенности карточка не показывается |
| `CONFIDENT_P` | из `confidence.json` (0.30) | выше — карточка показывается без оговорок |
| `EVAL_ABSTAIN` | `1` | `/v1/eval/predict` отвечает `{"slug": null}` ниже `EVAL_ABSTAIN_P`, если VLM не подтвердил лидера; `0` — всегда лучший кандидат (`docs/organizer_questions.md`, `pipeline/eval_scoring.py`) |
| `EVAL_ABSTAIN_P` | `SHOW_P` | порог отказа оценочного эндпоинта |
| `TEXT_ALIASES` | `1` | сведение латиницы и кириллицы в текстовом канале (Tamagne/Тамань, Chardonnay/Шардоне, имя винодельни) |
| `OCR_JOIN` | `1` | склейка разрядки и разрыва слова в строках OCR («Б Р ЮТ», «КРАСН OE») |
| `NAME_FIRST` | `1` | уверенно прочитанное имя вина заводит его владельца в группу текстового сравнения |
| `LINE_BAND` | `1` | отбор центральных слов OCR по строкам, а не по словам («ПОЛУСЛАДКОЕ РОЗОВОЕ» не режется пополам) |
| `PLATFORM_SWEETNESS` | `1` | сладость из карточки платформы там, где slug её не содержит |
| `NAME_STRONG` | `1` | точное прочитанное имя от 7 букв приводит владельца в группу сравнения без порога по точкам, все впереди него сравниваются |
| `NAME_TRANSLIT` | `1` | латинские имена собственные в названиях сводятся к кириллице побуквенно (Di Caspico = Ди Каспико) |
| `GROUP_LEADER` | `0` | текущий лидер всегда в группе сравнения; отвергнуто по замеру (−1 на tune) |
| `DEMOTE_GEOMETRY` | `0` | после отвода противоречащих кандидатов геометрия решает заново; верно на транскрипции, при текущем OCR не срабатывает |
| `DEMOTE_DEPTH` | `0` | при прочитанных цвете и сладости отвод без ограничения глубины; то же |
| `GEOM_WEIGHT` | `0` | экспериментальный порядок геометрии: вес точки запроса делится по числу позиций, где она инлаер; отвергнуто по замеру (α=1.0 −2 на tune, α=0.5 ±0), см. docs/metrics.md |
| `GEOM_WEIGHT_ALPHA` | `1.0` | показатель степени веса при `GEOM_WEIGHT=1` |
| `PLATFORM_ADDITIONS` | `1` | действует, только если собран `data/datapack/platform_additions.json` (`sync_platform.py`); в сдаваемой версии его нет |
| `VLM_CONFIRM` | `1` | ниже порога показа лидера проверяет Qwen3-VL-4B («тот же товар?»); при P(yes) ≥ `VLM_CONFIRM_P` ответ показывается как спорный и не уходит в отказ. ~9 ГБ видеопамяти, ~0.35 с на вызов; без CUDA выключается сам (`/health` → `settings.vlm_active`) |
| `VLM_CONFIRM_P` | `0.8` | порог P(yes) для подтверждения |
| `VLM_FALLBACK` | `2` | если лидер не подтверждён и ответ ушёл бы в отказ, VLM проверяет ещё столько следующих кандидатов; первый с P(yes) ≥ `VLM_CONFIRM_P` становится ответом |
| `VLM_GEO_FALLBACK` | `1` | второй проход при отказе: VLM отвергла лидера (P(yes) < 0.5), никто не дотянул до `VLM_CONFIRM_P`, но у проверенного кандидата P(yes) > 0.5 и геометрия за него — не меньше 80% точек лучшего и в 1.5 раза больше, чем у лидера; новых вызовов VLM нет |
| `VLM_CONTRA` | `1` | ответ показан, но уверенно прочитано слово чужой карточки, которого у лидера нет: VLM проверяет лидера, и если отвергает (P(yes) < 0.5) — владельцев слова |
| `VLM_CONTRA_P` | `0.7` | порог подтверждения владельца слова в этом пути |
| `VLM_BUDGET_MS` | `0` | бюджет времени на дополнительные вызовы VLM от начала поиска; 0 — без ограничения |
| `VLM_MODEL` | `Qwen/Qwen3-VL-4B-Instruct` | модель подтверждения |
| `VECTOR_BACKEND` | `numpy` | `pgvector` — векторы индекса в PostgreSQL (`DATABASE_URL`) |
| `DATABASE_URL` | — | строка подключения к PostgreSQL с pgvector |

Веса модели уверенности и оба порога лежат одним файлом
`data/index/confidence.json`; его пишет `pipeline/calibrate.py --write`,
читают и сервис, и все отчёты. Переменные окружения нужны, чтобы подвинуть
порог без пересборки образа.

## Ограничения

- 12 позиций каталога из 2103 не имеют эталонного фото в датасете кейса
  (в дампе нет файла, или файл из CSV показывает другое вино либо
  сгенерированную картинку без этикетки), то есть не попадают в индекс и
  не находятся ни при каком запросе. Список — `data/datapack/photo_overrides.csv`
  и `pipeline/check_refs.py`; сторонними фото пробелы не закрываются.
- Четыре фотографии платформа поставила сразу двум позициям каждая (два
  винтажа или два сорта одной винодельни) — такие пары неразличимы по фото.
- Почти-дубли, различающиеся только крепостью, неразличимы по фотографии
  лицевой этикетки — крепость на ней не напечатана.
- Эталоны каталога местами отстают от полки. Проверено восемь позиций
  сравнением с товарными страницами магазинов и производителей
  (`pipeline/check_freshness.py`): устарела одна — «Абрау Купаж тёмный»,
  у неё в каталоге упаковка прошлого поколения, и реальные снимки не
  находятся. Выборка мала, доля может быть любой от единиц до десятков
  процентов, но систематическим отставание по этим данным не выглядит.
- robots.txt платформы закрывает `/api/*` для ботов. Обход каталога
  использовался для полей, которых нет в выгрузке кейса; для эксплуатации
  нужна договорённость с платформой.

## Структура

```
pipeline/   подготовка данных, ядро поиска, замеры
service/    HTTP API и рекомендации
web/        Nuxt-модуль в стилистике портала
dataset/    данные кейса (не в репозитории)
data/       каталог, индексы, валидационные наборы (генерируются)
docs/       расширенная документация и методика оценки
```
